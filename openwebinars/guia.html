📘 Añadir un proyecto paso a paso

Cada proyecto nuevo es una carpeta dentro de openwebinars/ con su propio index.html. Esta guía usa la plantilla _plantilla/ para que solo tengas que cambiar el contenido.

🗂️ Estructura final

openwebinars/ ├── index.html ← portada con la lista de proyectos ├── guia.html ← esta guía ├── _plantilla/ ← plantilla base (no se publica) │ ├── index.html │ ├── css/estilos.css │ └── js/app.js ├── ejemplo/ ← proyecto de ejemplo │ ├── index.html │ ├── css/estilos.css │ └── js/app.js └── mi-proyecto/ ← el proyecto nuevo ├── index.html ├── css/estilos.css └── js/app.js

1 Duplica la plantilla

Sitúate en la carpeta openwebinars/ del repositorio y copia _plantilla con el nombre de tu proyecto. Usa minúsculas, sin espacios ni tildes (mejor guiones): mi-proyecto, ejercicios-dom, etc. 

cd openwebinars
cp -r _plantilla mi-proyecto
💡 Si prefieres hacerlo desde el explorador de archivos, copia y pega la carpeta _plantilla y renómbrala.

2 Personaliza el proyecto

Edita estos tres archivos dentro de la carpeta nueva:

  • index.html: cambia el título, el encabezado y el contenido.
  • css/estilos.css: adapta colores, tipografía y diseño.
  • js/app.js: añade la lógica y los console.log que quieras.

El HTML ya incluye las rutas relativas correctas:

<link rel="stylesheet" href="css/estilos.css">
<script src="js/app.js"></script>
⚠️ No uses rutas absolutas como /css/estilos.css: el sitio se publica en un subdirectorio y dejarían de funcionar.

3 Añade la tarjeta en la portada

Abre openwebinars/index.html y busca el comentario AÑADIR NUEVO PROYECTO. Copia el bloque de la tarjeta de ejemplo y cámbialo: 

<a class="card" href="mi-proyecto/">
  <span class="icon">🚀</span>
  <h3>Mi proyecto</h3>
  <p>Descripción breve de lo que hace el proyecto.</p>
  <span class="tag">HTML · CSS · JS</span>
</a>

La ruta del href debe terminar en / y coincidir con el nombre exacto de la carpeta.

4 Pruébalo en local

Desde la raíz del repositorio, levanta un servidor estático. No abras el HTML con doble clic: algunas rutas y peticiones necesitan http://. 

cd /ruta/a/escomz.github.io
python3 -m http.server 8000

Abre en el navegador:

http://localhost:8000/openwebinars/
http://localhost:8000/openwebinars/mi-proyecto/

Comprueba que se ven los estilos, que la consola (F12) no da errores y que los enlaces funcionan.

5 Guarda los cambios en Git

git add openwebinars
git commit -m "feat(openwebinars): añadir proyecto mi-proyecto"
git push

Si estás trabajando en una rama (por ejemplo con worktrunk), haz push de esa rama y mézclala en main cuando el proyecto esté listo.

6 Comprueba el resultado publicado

GitHub Pages tarda aproximadamente un minuto en publicar los cambios:

https://escomz.github.io/openwebinars/
https://escomz.github.io/openwebinars/mi-proyecto/

El visor de código detecta automáticamente las carpetas que contienen un index.html, también las que están dentro de openwebinars/. No hace falta tocar visor.html.

✓ Lista de comprobación

  • La carpeta está dentro de openwebinars/ y usa minúsculas sin espacios.
  • Existe openwebinars/mi-proyecto/index.html.
  • Las rutas de CSS y JS son relativas.
  • La tarjeta de openwebinars/index.html apunta a mi-proyecto/.
  • Probado en http://localhost:8000/openwebinars/mi-proyecto/.
  • Commit y push realizados; la URL pública responde.

📌 Reglas rápidas

  • Un proyecto = una carpeta con index.html.
  • No subas node_modules/ (ya está en .gitignore).
  • Evita carpetas que empiecen por _ para proyectos reales: GitHub Pages las ignora (por eso la plantilla no se publica).
  • Si el proyecto necesita compilación (TypeScript, bundlers), sube también el resultado final que consume el navegador.
