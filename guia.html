Cómo copiar tus proyectos a otro PC + explicación de TypeScript (para clase)

Parte 1 — Guía para nuevo PC

1. Instalar git (y Node.js opcional)

sudo apt install git
# Node.js solo si vas a compilar TypeScript:
# https://nodejs.org (LTS)

2. Configurar tu identidad (una sola vez)

git config --global user.name "escomz"
git config --global user.email "32931135+escomz@users.noreply.github.com"
El email 32931135+escomz@users.noreply.github.com es el noreply de tu cuenta. GitHub bloquea los pushes con tu correo real por privacidad.

3. Clonar tu repositorio

Opción SSH (sin escribir contraseñas cada vez):

git clone git@github.com:escomz/escomz.github.io.git
cd escomz.github.io

Opción HTTPS (piden usuario y token):

git clone https://github.com/escomz/escomz.github.io.git

4. Compilar el TypeScript del proyecto

cd escomz.github.io/proyecto1
npm install          # instala typescript (solo la primera vez)
npm run build        # src/script.ts → compiled/script.js
npm run watch        # opcional: recompila al guardar cambios

5. Publicar cambios

git add .
git commit -m "Descripción del cambio"
git push
GitHub Pages publica los cambios solos en ~1 minuto en https://escomz.github.io/proyecto1/

6. Configurar SSH desde cero

ssh-keygen -t ed25519 -C "tu correo"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
  • Copia todo lo que empiece por ssh-ed25519...
  • Pégalo en github.com/settings/keys → New SSH key
  • Prueba: ssh -T git@github.com → debe decir Hi escomz!

Parte 2 — Explicación de clase

El problema: el navegador no ejecuta TypeScript

TypeScript (TS) es un superconjunto de JavaScript: añade tipos y funciones, pero el navegador solo entiende JS. Si cargas un .ts con <script>, el navegador lo ignora y la página no hace nada.

src/script.ts  ──(tsc)──▶  compiled/script.js  ──▶  el navegador lo ejecuta
 (fuente, TS)            (traducción, JS)

Las herramientas creadas

FicheroFunción
package.jsonDefine el proyecto y el comando npm run build / npm run watch
tsconfig.jsonDice a tsc: lee de src/, escribe en compiled/, con strict: true (tipos obligatorios)

El bug: dos scripts, un mismo elemento

JavaScript y TypeScript escribían ambos en el mismo <h1 id="mensaje">. Orden real de ejecución:

  1. El navegador lee el HTML de arriba abajo
  2. El script compilado de TS se ejecuta ya mismo → escribe su mensaje
  3. script.js usa DOMContentLoaded, así que espera a que cargue todo
  4. Al terminar la carga, sobrescribe el mensaje del TS
Resultado: el mensaje TypeScript nunca se veía, aunque el código era correcto.

La solución: un elemento por script

ScriptElementoMensaje
script.js (JS a mano)#mensajeHola Mundo (JavaScript)
src/script.ts (compilado)#mensaje-tsHola Mundo (TypeScript)

Cada script tiene su propio h1: conviven en pantalla y se distingue de un vistazo qué genera cada lenguaje.

Ideas clave para recordar

  • Compilar = traducir TS a JS con tsc (npm run build)
  • Tras editar el .ts hay que recompilar, recargar no basta
  • DOMContentLoaded retrasa la ejecución hasta que el HTML está cargado
  • Si dos scripts tocan el mismo elemento, el último en ejecutarse gana
